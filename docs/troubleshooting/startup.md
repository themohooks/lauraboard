# Как устранить проблемы запуска и подключения

## Окно не открывается или рисуется неправильно

**Симптом:** пустое окно, артефакты, сбой в удалённом рабочем столе. Возможная причина — графический backend или драйвер; конкретный сбой требует журнала.

1. Проверьте, не скрыто ли окно в трее. Повторный запуск для того же сервера может активировать существующее.
2. Запустите из PowerShell с программной отрисовкой:

```powershell
$env:SLINT_BACKEND = "winit-software"
lauraboard -p "D:/TV/MyChannel" gui
Remove-Item Env:SLINT_BACKEND
```

3. Если окно появилось, оставьте этот способ для диагностики и проверьте драйвер с администратором.
4. Если нет — сохраните точный текст ошибки терминала и версию для [поддержки](../support.md).

Команда не сбрасывает проект. Не удаляйте медиа и `state/` ради проблемы отрисовки.

## FFmpeg или ffprobe не найдены

**Подтверждённый фрагмент журнала:** `ffmpeg not found`. Параметры команды и путь добавляются программой.

1. Выполните `ffmpeg -version`, затем `ffprobe -version` в среде, из которой запускается движок.
2. Если команды не найдены, установите компоненты либо задайте полные пути в `[ffmpeg]` файла `lauraboard.toml`.
3. Перезапустите процесс после изменения PATH. Служба и интерактивный пользователь могут иметь разные переменные и права.
4. Повторите `lauraboard -p "D:/TV/MyChannel" validate`, затем тестовый запуск.

## Как восстановить связь и доступ

**Сообщения:** `Нет связи с сервером: …`, **Нет доступа: неверный или отсутствующий токен API**, **Недостаточно прав: …**.

1. Проверьте **Настройки → Подключение → Сервер API**.
2. Убедитесь, что отдельный движок запущен, адрес и порт верны. При встроенном запуске проверьте проект и журнал запуска.
3. Для удалённого подключения проверьте сеть и разрешённый доступ с администратором. Не отключайте защиту ОС как универсальное решение.
4. Для ошибки токена перезапустите GUI с правильным токеном; для недостаточных прав запросите роль, соответствующую операции.
5. Ожидаемый результат: **Связь есть**, список каналов загружается и чтение статуса работает.

Полная процедура — [подключение](../guides/connection.md). Перезапуск клиента не должен заменять диагностику остановившегося сервера.

## Канал уже запущен в другом процессе

**Сообщение:** `channel '<id>' is already running in another process` / **Канал «…» уже запущен в другом процессе**.

1. Найдите работающий GUI, `run` или службу, использующую тот же проект.
2. Подключитесь к её API вместо запуска второго движка.
3. Если нужен перезапуск, штатно остановите именно этот экземпляр. Не удаляйте файл блокировки при живом процессе.
4. После остановки повторите запуск и проверьте один работающий экземпляр.
