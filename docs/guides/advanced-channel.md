# Как настроить резерв, последовательный эфир и дополнительные параметры

> LauraBoard 0.1.0. Снимки показывают реальный интерфейс; демонстрационные состояния подписаны отдельно. Способы и пределы проверки перечислены в [отчёте](../verification.md).

Некоторые функции доступны через конфигурационные файлы или CLI и не имеют отдельной формы в GUI. Здесь действия для таких случаев; при сомнении передайте их администратору.

**Потребуется:** независимая [копия проекта](backup-restore.md). Сначала сохраните черновики, остановите эфир и движок, затем редактируйте копию конфигурации. Не создавайте повторные секции TOML поверх существующих.

## Как подготовиться к действиям вне интерфейса

Этот раздел предназначен для операций, для которых нет полной формы GUI. Если вы впервые работаете с файлами настроек, выполняйте их вместе с администратором после [копирования проекта](backup-restore.md).

1. Узнайте корень нужного проекта и идентификатор канала. Пример `channels/<id>/channel.toml` — путь внутри проекта, где `<id>` заменяется вашим идентификатором без скобок.
2. Сохраните черновики и остановите использующий этот проект движок. Закрытие одного удалённого окна не останавливает сервер.
3. Создайте копию изменяемого файла. Откройте исходный текстовым редактором; сохраняйте исходное расширение, не превращая `.toml` или `.json` в `.txt`.
4. Измените существующее поле или секцию по примеру. Не добавляйте вторую одноимённую секцию TOML. В JSON соблюдайте кавычки, запятые и скобки.
5. В терминале выполните команду проверки с явным `-p` вашего проекта. Если ошибка указывает файл и строку, исправьте именно их до запуска.
6. Запустите локальную проверку без рабочих выходов. Если результат неверен, остановите движок и верните копию файла.

Идентификаторы материала, плейлиста и блока не взаимозаменяемы. Перед подстановкой запишите требуемый идентификатор из соответствующего объекта; видимое название «Утро» не обязательно равно его `id`.

## Как настроить резервный ролик и картинку

1. Добавьте резервный ролик в медиатеку, запишите его идентификатор. Картинку положите в доступный проекту каталог.
2. В существующем `channels/<id>/channel.toml` найдите `[fallback]`.
3. Задайте `media = "<id ролика>"`, для картинки — `image = "media/standby.png"`, заменив путь реальным.
4. Выполните `lauraboard -p "<папка проекта>" validate` и исправьте ошибки.
5. Запустите только локальную проверку. Если нет доступного основного контента, проверьте резерв.

![Обзор резерва](../screenshots/interface/sources-light.png)

В «Источники и сцены» виден обзор резервной картинки и ролика. Этот обзор не является формой редактирования `[fallback]`.

## Как вещать плейлист последовательно без сетки

1. Создайте и сохраните плейлист в GUI.
2. В существующей секции `[planning]` канала задайте `mode = "sequential"` и `playlist = "<id плейлиста>"`.
3. Проверьте `validate`, затем `plan --hours 1` для нужного проекта и канала.
4. Запустите тестовый эфир. Для возврата восстановите прежнюю секцию планирования из копии; для сетки используется `mode = "grid"`.

Параметры `horizon`, `seed`, `history` задают горизонт прогноза, воспроизводимость случайного выбора и учитываемую историю. Их форматы и значения описаны в [конфигурации](../configuration.md). Изменение seed может изменить прогноз, а удаление истории — повлиять на учёт повторов.

## Как задать теги, метаданные и границы материала

1. Для тегов используйте `media set <id> --tags "news,studio"` с правильным проектом.
2. Для привязки анонса к блоку доступно `media set <id> --promo-block <id блока>`.
3. Для произвольных `meta`, более точной привязки `promo`, `in_point` и `out_point` измените соответствующий элемент `library.json` на остановленной копии проекта по [схеме](../configuration.md).
4. Метаданные, например `presenter`, становятся доступными в тексте графики. Точки входа и выхода ограничивают показ исходного ролика; не задавайте пустой диапазон.
5. Проверьте JSON, `validate`, прогноз и фактический показ. Для отмены верните прежнюю запись из копии.

## Как подготовить будущее расписание и серверные уведомления

Будущее расписание активируется через `activate_at` в его настройках. Поля `notify.webhook` и `notify.command` задаются глобально в `lauraboard.toml`; это отдельный механизм от всплывающих карточек GUI. Настройку выполняет администратор по [справочнику](../configuration.md), с проверкой получателя и передаваемых сведений. Внешняя доставка уведомлений здесь не проверялась.

Глобальные пути FFmpeg, API, токены, журналирование и службы также описаны в технических справочниках. После ручного изменения остановленных файлов перезапустите движок; не запускайте восстановленную конфигурацию с рабочими выходами без локальной проверки.
