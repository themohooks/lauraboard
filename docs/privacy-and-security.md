# Конфиденциальность и безопасная работа с данными

Проект может содержать видео, пользовательские названия и пути, сетевые адреса, ключи трансляций, токены API и историю эфира. Скрытый ключ в GUI не означает шифрования файла конфигурации.

## Какие данные могут уходить по сети

- Видео и звук направляются в настроенные точки вещания.
- Потоки и удалённые медиа читаются с заданных источников.
- GUI запрашивает данные и отправляет команды серверу API; события получает по WebSocket.
- Google Fonts требует сетевого обращения сервера за каталогом и файлами шрифтов.
- При настроенном webhook события отправляются на указанный адрес. Внешняя команда уведомлений может обрабатывать данные события.

Наличие или отсутствие иных механизмов сбора данных не подтверждено отдельным сетевым аудитом. Не делается утверждений о сертификации, шифровании архивов или полном отсутствии телеметрии.

## Как обращаться с доступом

Используйте права по задаче и не публикуйте токен. Без настроенных токенов сервер разрешает локальные loopback-запросы с admin и отклоняет внешние. При внешнем размещении администратор должен настроить доступ и защищённый транспорт; обычный HTTP не обеспечивает конфиденциальность токена.

Токен событий может присутствовать в URL WebSocket. В журнале, снимке сетевого окна или описании ошибки проверяйте query-параметры, заголовки и полные адреса потоков.

## Как подготовить материалы для поддержки

1. Сделайте копию журнала, не правьте единственный оригинал.
2. Уберите Bearer-токены, query-токены, ключи в URL, пароли и закрытые адреса.
3. Уберите личные имена, пути профиля и сведения из самих видеокадров, если они не нужны для диагностики.
4. Проверьте архив: экспорт с **Выходы и ключи трансляций** и конфигурационный `backup` могут содержать секреты.
5. Передавайте только необходимый материал по согласованному каналу.
